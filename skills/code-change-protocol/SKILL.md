# 代码改动规约

## 核心优先级

正确性 > 最小修改 > 代码一致性 > 性能优化

## 1. 任务路由（动手前先判档）

| 档位 | 适用 | 流程 |
|------|------|------|
| 🟢 DIRECT | 单函数 bug、单文件小幅修正、变量/逻辑改错 | 改代码 → VERIFY |
| 🔵 LIGHT（计划 ≤5 行） | 单模块功能、局部 API 调整、小范围结构改动 | 极简 PLAN → 实现 → VERIFY |
| 🔴 FULL | 多文件、架构/数据结构变更、跨模块改动 | PLAN → IMPLEMENT → VERIFY → REVIEW |

改动公共接口、数据结构、跨模块逻辑 → 自动升级 FULL，先梳理全量调用链与数据流。

## 2. PLAN（唯一事实源）

PLAN 只写实时计划（做什么、分几步）与核心内容：变量、Model/DTO、API、函数签名等契约定义；不写实现代码（函数体、具体逻辑）。实现阶段只能使用 PLAN 定义的内容，禁止额外新增。不确定实现立刻停止，向用户确认。

## 3. IMPLEMENT

新增前必走：

1. YAGNI：确认必须新增再写
2. 复用优先级：当前模块 > 相似模块 > 公共模块；标准库 / 原生 API / 现有依赖优先
3. 无法复用才新增最小代码

修改约束：diff 范围最小；不动无关代码、空格、换行、格式、原有结构；不做计划外的变量新增、架构改动、性能优化、风格重构。定位后局部逻辑用 Edit 最小替换，不为凑工具整函数重写。

## 4. VERIFY（交付前必做）

自查：未定义变量、类型错误、缺失导入、调用断裂、运行风险；失败先修复再输出。仓库无自动化测试时如实说明，不把「起服务」当测试通过。

## 5. 检索定位

优先已安装的 Skill / MCP / 插件。代码关系类问题走 CodeGraph：业务自然语言首查 → 技术词（DOM id、class、函数名片段）重查 → 两次不中才允许 Grep/Glob/Read 兜底，并在交付说明中讲清降级原因。hook 已强制执行；禁止为凑规则无意义调用工具。

CodeGraph 返回繁忙/超时/database is locked 时：重试一次，仍失败走 Grep/Glob/Read 兜底并在交付说明讲清降级原因，勿连续猛调。两个繁忙高峰：会话刚启动的 catch-up reconcile、大批量文件改动（切分支/install/build）后。锁死不恢复用 `codegraph daemon` 重启或 `codegraph unlock`，禁止手删 `.codegraph/`（全量重建代价大）。索引减负用项目根 `codegraph.json` 的 `exclude`（node_modules/dist 等已内置忽略），改后执行 `codegraph index` 重建。

## 6. 规约演进（本套规则如何迭代）

**沉淀信号（满足其一才触发）：**

- 用户明确说「记住 / 以后都这样 / 写进规约」
- 同类问题被纠正第 2 次（单次不沉淀，避免噪音）
- 发现规则之间冲突、重复，或与实际代码不符

**落点分层（先判断写哪一层）：**

| 内容 | 落点 |
|------|------|
| 跨项目硬红线、禁律 | 用户级指令文件（CLAUDE.md / `~/.codex/AGENTS.md` / `~/.gemini/GEMINI.md`） |
| 可复用流程、方法、判据 | 本 skill；体量够大则独立新 skill |
| 单项目事实与约定 | 项目级指令文件（CLAUDE.md / AGENTS.md / GEMINI.md） |
| 一次性事实、人的偏好、项目状态 | memory |

能用 settings.json / hook 强制执行的（禁用工具、权限约束等），不写成文字规则。

**变更流程：** 提议（规则原文 + 落点 + 理由）→ 用户确认 → 最小改动落盘 → 顺手检查重复与失效条目，合并或退役 → 若落点是 claude-code-kit 套件仓库的分发源文件（`agent.md`、`supplements/`、`skills/`、`hooks/`、`settings.snippet.json`），立即在仓库根执行 `node install.mjs` 把变更同步到本机生效副本并回报安装输出；项目级指令、memory 的改动不触发。git commit/push 始终由用户执行。

**退役：** 规则连续不适用、被配置取代、或与新规则冲突 → 提议删除，同样需确认。

**只增不减等于没迭代：** 每次新增必须回答「哪条旧规则可以合并」。

## 7. 交付输出

默认仅输出：修改文件列表、改动说明、VERIFY 结果。不写冗余长篇解释。
